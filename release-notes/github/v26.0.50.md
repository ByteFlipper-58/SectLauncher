# SectLauncher v26.0.50

## Overview

This release bundles the work shipped between **2026-05-10** and **2026-08-03**.

The main focus of this build is:

- a full **Skins & Capes** section with 3D preview, skin library, and cape management
- complete **offline skin/cape support** through bundled CustomSkinLoader
- a redesigned settings layout built on a shared settings UI kit
- responsive layout work across Instances, Mods, and Worlds
- frontend performance work: debounced search, memoized cards, lazy-loaded mod detail
- centralized cache configuration, error mapping, and audit wrapping on the Rust side
- build and CI optimizations for smaller binaries and faster compiles

## What's Changed

### Skins and capes

A dedicated Skins & Capes section was added to the sidebar, covering both Microsoft and offline accounts.

- Added a **Skins & Capes** page with responsive layouts, loading shimmer, and sidebar focus-mode support.
- Added a reusable 3D preview with classic/slim models, outer layers, cape rendering, selectable poses, and animation controls.
- Added a skin library supporting create, copy, rename, edit, apply, and delete, keeping the active skin deduplicated and correctly ordered.
- Bundled all official Mojang default skins (Steve, Alex, Ari, Efe, Kai, Makena, Noor, Sunny, Zuri) in both wide and slim variants.
- Added cape selection, local cape uploads, activation, deactivation, and editor previews.
- Added drag-and-drop PNG uploads with optimized thumbnail rendering for skins and capes.
- Added account-scoped libraries and cached default textures.
- Registered `skins` as an app tab and added it to the default content focus tabs.
- Added localized UI strings for the new section across `en_us`, `ru_ru`, `pl_pl`, and `uk_ua`.

Relevant commits:
- `b358451` feat: add full skin and cape management with offline support

### Offline skin and cape support

Offline accounts now get working skins and capes in modded instances without relying on any third-party skin service.

- Added validated PNG texture handling with immutable hash-based per-account storage and safe local path handling.
- Bundled the official unmodified `CustomSkinLoader_Universal-15.0.1.jar` with its GPL-3.0 license notice and recorded SHA-256.
- LocalSkin textures are prepared automatically for supported Forge, NeoForge, Fabric, and Quilt instances.
- Offline instances are configured to use only SectLauncher-managed LocalSkin textures.
- Selected skins and capes are synchronized before launch, and disabled cape files are removed.
- Microsoft accounts continue to go through the official Minecraft Services API.
- Added `THIRD_PARTY_NOTICES.md` documenting the bundled Mojang skin textures and the CustomSkinLoader binary.

Relevant commits:
- `b358451` feat: add full skin and cape management with offline support

### Authentication

- Improved authentication error handling and token refresh behavior so raw service responses are no longer surfaced to the UI.
- Added a 300-second deadline to Microsoft device-code polling with a user-facing timeout message instead of polling indefinitely.
- Enabled `multipart` on the HTTP client for skin upload support.

### Settings layout

The settings area was refreshed to make configuration easier to scan and visually consistent across sections.

- Added a shared `settingsUiKit` with `SectionPageHeader`, `SettingsGroupHeading`, `SettingsCard`, `SettingsRow`, and `SettingsToggle`.
- Reworked the appearance, game, general, system, privacy, storage, logs, update, and catalog cache sections onto the shared kit.
- Consolidated related settings styles and reduced duplicated per-section markup.

### Responsive layout across Instances, Mods, and Worlds

A large layout pass introduced semantic CSS classes and adaptive behavior so the main content pages hold up at small window sizes.

- Introduced semantic CSS tokens and classes: `page-header`, `sidebar-account-row`, `instances-page`, plus worlds/mods toolbars, filters, and grids.
- Added adaptive behavior for the Instances, Mods, and Worlds pages, and consolidated many overlapping style rules.
- Added installed-grid sizing constants (`INSTALLED_CARD_MIN_WIDTH`, `INSTALLED_GRID_GAP`, `INSTALLED_MAX_COLUMNS`).
- Reworked `getInstalledGridColumns` to derive columns from the measured grid width instead of fixed CSS breakpoints, keeping the virtualized installed grid as the single source of truth.
- Improved modal layout and accessibility with proper titles and `aria-label` coverage.
- Refined small-window responsiveness, card sizing, preview positioning, control layouts, and scroll behavior.

### Frontend performance

- Added a shared performance module with `useDebounce`, `useThrottle`, `useLazyRef`, and `useEvent`.
- Debounced the search inputs in the Mods and Worlds UIs so filtering runs after typing stops rather than per keystroke.
- Made the mods and worlds search bars sticky while scrolling results.
- Memoized `ModCard` and `LocalModCard` to avoid unnecessary re-renders.
- Lazy-loaded `ModDetail` behind `Suspense` to cut the initial bundle.

Relevant commits:
- `7ccc68d` Add performance hooks, lazy load & build optimizations

### Caching, error handling, and audits

Backend duplication was reduced around the three patterns that had spread widest across command handlers.

- Introduced `shared::CacheConfig` and `infrastructure/downloader/cache_helpers.rs` encapsulating hashing, load/persist, and enabled checks.
- Updated the Modrinth and CurseForge downloader modules to use the shared config and helpers, and unified cache scope constants.
- Added a `shared::StrErr` extension, replacing repetitive `map_err(|e| e.to_string())` calls with `.str_err()`.
- Replaced manual `audit_start`/`audit_success`/`audit_failure` sequences with a `run_audited` wrapper across catalog, downloader, instances, updates, and worlds command handlers.
- Centralized the Modrinth HTTP client and user-agent.

### Build and CI

- Added `rollup-plugin-visualizer` and refined `manualChunks` to split vendors into `vendor-react`, `vendor-i18n`, `vendor-markdown`, `vendor-icons`, and `vendor-misc`.

## Upgrade Notes

- Skins and capes for offline accounts require a supported modded instance (Forge, NeoForge, Fabric, or Quilt); CustomSkinLoader is prepared automatically and the bundled binary is unmodified.
- Offline skin and cape textures are stored per account under launcher-managed storage using content hashes, so existing accounts start with an empty library.
- Microsoft account skin and cape behavior is unchanged and still goes through the official Minecraft Services API.
- Microsoft device-code login now fails after 5 minutes of polling instead of waiting indefinitely; restart the login flow if it times out.
- The settings and layout work is presentational and preserves existing user settings.
- The release profile change (`lto = "thin"`, `opt-level = "z"`) targets binary size; if you build locally, expect different compile characteristics than before.
